# «Attention Is All You Need» (2017): подробный разбор на русском

**Оригинал:** Vaswani, Shazeer, Parmar, Uszkoreit, Jones, Gomez, Kaiser, Polosukhin. *Attention Is All You Need.* NIPS 2017. [arXiv:1706.03762](https://arxiv.org/abs/1706.03762)

## Аннотация: о чём статья

Задача, которую решают авторы, — **преобразование последовательностей** (sequence transduction): на вход одна последовательность, на выход другая. Главный пример — машинный перевод.

В 2017 году лучшие модели для этого строились на рекуррентных (RNN) или свёрточных (CNN) сетях со схемой «энкодер — декодер», а части модели соединял механизм внимания. Авторы предлагают архитектуру **Transformer**, которая отказывается от рекуррентности и свёрток целиком и опирается **только на внимание**.

Результат: перевод лучше, чем у всех предыдущих моделей, при этом обучение сильно параллельнее и быстрее. На переводе с английского на немецкий (WMT 2014) — 28,4 BLEU, на 2 с лишним пункта выше прежнего лучшего результата. На английском → французском — 41,8 BLEU после 3,5 дня обучения на 8 GPU. Плюс модель хорошо переносится на другую задачу: синтаксический разбор английских предложений.

> **Комментарий.** BLEU — стандартная метрика качества машинного перевода: насколько перевод модели совпадает по словам и словосочетаниям с эталонным человеческим переводом. Шкала от 0 до 100, прирост в 1–2 пункта в этой области считался серьёзным.

## 1. Введение: в чём была проблема

До трансформера стандартом были рекуррентные сети (в частности LSTM и GRU). Они читают последовательность **по одному элементу**: состояние на шаге `t` вычисляется из состояния на шаге `t−1` и очередного входа.

Отсюда главное ограничение: шаги нельзя считать параллельно. Пока не посчитан шаг 99, нельзя начать шаг 100. На длинных последовательностях это бьёт по скорости обучения, а GPU, которые сильны именно в параллельных вычислениях, простаивают. Были приёмы, частично ускоряющие RNN, но фундаментальная последовательность вычислений оставалась.

Механизм внимания к тому моменту уже существовал и хорошо работал: он позволяет связывать элементы последовательности независимо от расстояния между ними. Но почти всегда его использовали **в дополнение** к рекуррентной сети.

Идея статьи: убрать рекуррентность совсем и оставить только внимание. Такая модель параллелится гораздо лучше и, по словам авторов, достигает нового лучшего качества перевода уже после 12 часов обучения на восьми GPU P100.

## 2. Предпосылки

Сократить последовательные вычисления пытались и раньше, через свёрточные сети (Extended Neural GPU, ByteNet, ConvS2S). Они считают все позиции параллельно, но у них другая беда: чтобы связать два далёких элемента, сигнал должен пройти через много слоёв. Число операций на путь растёт с расстоянием (линейно у ConvS2S, логарифмически у ByteNet), и дальние зависимости учатся хуже.

В трансформере путь между любыми двумя позициями занимает **постоянное** число операций. Цена — внимание усредняет информацию по многим позициям и может «размывать» детали. Это авторы компенсируют многоголовым вниманием (раздел 3.2).

**Self-attention** (внутреннее внимание) — внимание, при котором элементы одной и той же последовательности смотрят друг на друга, чтобы построить её представление. Его уже применяли в задачах понимания текста и суммаризации. Новизна статьи в том, что это первая модель преобразования последовательностей, построенная **только** на self-attention, без RNN и свёрток.

## 3. Архитектура модели

Общая схема та же, что у предшественников: **энкодер** читает вход `(x₁, …, xₙ)` и превращает его в последовательность векторов `z = (z₁, …, zₙ)`. **Декодер** по `z` генерирует выход `(y₁, …, yₘ)` по одному элементу, на каждом шаге получая на вход уже сгенерированные элементы. Такая генерация называется **авторегрессионной**.

На рисунке 1 статьи энкодер слева, декодер справа.

> **Комментарий.** Современные LLM (GPT, Claude, Qwen, gpt-oss) используют только правую половину рисунка — декодер, и без среднего блока «внимания к энкодеру». Такую схему называют decoder-only. Энкодер нужен для перевода, где есть отдельный входной текст, а языковой модели достаточно продолжать одну последовательность.

### 3.1. Энкодер и декодер

**Энкодер** — стопка из `N = 6` одинаковых слоёв. В каждом два подслоя:
1. многоголовое self-attention;
2. простая полносвязная сеть, применяемая к каждой позиции отдельно.

Вокруг каждого подслоя стоит **остаточная связь** (residual connection), а после неё **нормализация слоя** (layer normalization). То есть выход подслоя:

```
LayerNorm(x + Sublayer(x))
```

Чтобы складывать `x` и `Sublayer(x)`, все подслои и эмбеддинги выдают векторы одной длины: `d_model = 512`.

**Декодер** — тоже 6 слоёв, но в каждом три подслоя: к двум из энкодера добавляется третий, внимание к выходу энкодера. Self-attention в декодере **замаскировано**: позиция не может смотреть на позиции после себя. Вместе со сдвигом выхода на одну позицию это гарантирует, что предсказание для позиции `i` зависит только от уже известных элементов до `i`.

> **Комментарий.** Современные модели ставят нормализацию **перед** подслоем: `x + Sublayer(Norm(x))` (pre-norm). Так глубокие модели обучаются стабильнее. В нашей игрушке `sprint-01-llm-basics/toy-llm/toy_llm.py` сделано так же.

### 3.2. Внимание

Функция внимания отображает **запрос** (query) и набор пар **ключ — значение** (key — value) в выход. Все четыре — векторы. Выход — взвешенная сумма значений, где вес каждого значения определяется тем, насколько его ключ совместим с запросом.

#### 3.2.1. Scaled Dot-Product Attention (масштабированное внимание через скалярное произведение)

Запросы и ключи имеют длину `d_k`, значения — `d_v`. Для запроса считают скалярное произведение со всеми ключами, делят на `√d_k`, применяют softmax и получают веса для значений. На практике всё считается матрично, сразу для всех запросов:

```
Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k ) · V          (формула 1)
```

Авторы сравнивают это с **аддитивным** вниманием (совместимость считает маленькая сеть с одним скрытым слоем). По теоретической сложности они близки, но скалярное произведение на практике гораздо быстрее и экономнее по памяти: это просто перемножение матриц, для которого есть оптимизированный код.

**Зачем делить на √d_k.** При больших `d_k` скалярные произведения становятся большими по модулю, softmax уходит в область, где почти весь вес достаётся одному элементу, а градиенты становятся крошечными, и обучение буксует. Объяснение в сноске: если компоненты `q` и `k` — независимые случайные величины со средним 0 и дисперсией 1, то их скалярное произведение имеет дисперсию `d_k`. Деление на `√d_k` возвращает дисперсию к 1.

#### 3.2.2. Multi-Head Attention (многоголовое внимание)

Вместо одного внимания на векторах длины `d_model` авторы `h` раз проецируют запросы, ключи и значения разными выученными матрицами в меньшие размерности, считают внимание параллельно в каждой проекции («голове»), склеивают результаты и ещё раз проецируют:

```
MultiHead(Q, K, V) = Concat(head₁, …, head_h) · Wᴼ
где head_i = Attention(Q·W_iᵠ, K·W_iᴷ, V·W_iⱽ)
```

Смысл: разные головы могут одновременно смотреть на разные аспекты информации в разных позициях. С одной головой усреднение мешает это делать.

В статье `h = 8` голов, у каждой `d_k = d_v = d_model / h = 64`. Поскольку каждая голова меньше, суммарные вычисления примерно такие же, как у одной «полной» головы.

#### 3.2.3. Три применения внимания в модели

1. **Внимание энкодер — декодер:** запросы идут из декодера, ключи и значения из выхода энкодера. Каждая позиция декодера может смотреть на весь входной текст. Это классическая схема из предыдущих моделей перевода.
2. **Self-attention в энкодере:** запросы, ключи и значения берутся из выхода предыдущего слоя энкодера, и каждая позиция видит все позиции.
3. **Self-attention в декодере:** позиция видит все позиции до себя включительно. Чтобы информация не текла «справа налево» (из будущего), запрещённые связи маскируются: их значения перед softmax заменяются на `−∞`, и их вес становится нулевым.

> **Комментарий.** Пункт 3 — это ровно то, что есть в любой современной LLM. В нашей игрушке маска реализована проще: цикл `for j in range(i + 1)` просто не смотрит на будущие позиции.

### 3.3. Position-wise Feed-Forward Networks (полносвязные сети по позициям)

Кроме внимания, в каждом слое есть полносвязная сеть, которая применяется к каждой позиции отдельно и одинаково. Это два линейных преобразования с ReLU между ними:

```
FFN(x) = max(0, x·W₁ + b₁)·W₂ + b₂                       (формула 2)
```

Между позициями веса общие, между слоями — разные. Вход и выход имеют размерность `d_model = 512`, внутренний слой — `d_ff = 2048`, то есть в 4 раза шире.

### 3.4. Эмбеддинги и softmax

Входные и выходные токены переводятся в векторы длины `d_model` выученными эмбеддингами. Выход декодера превращается в вероятности следующего токена обычным линейным слоем и softmax. Авторы используют **одну и ту же матрицу** для обоих эмбеддингов и для финального линейного слоя (связывание весов), а в эмбеддингах умножают веса на `√d_model`.

### 3.5. Позиционное кодирование

В модели нет ни рекуррентности, ни свёрток, поэтому она сама по себе не знает порядка токенов. Информацию о позиции нужно добавить явно: к входным эмбеддингам прибавляются **позиционные кодировки** той же длины `d_model`.

Авторы используют синусы и косинусы разных частот:

```
PE(pos, 2i)   = sin( pos / 10000^(2i / d_model) )
PE(pos, 2i+1) = cos( pos / 10000^(2i / d_model) )
```

где `pos` — позиция, `i` — номер измерения. Каждому измерению соответствует синусоида, длины волн образуют геометрическую прогрессию от `2π` до `10000·2π`. Гипотеза авторов: так модели проще учиться смотреть на **относительные** позиции, потому что `PE(pos+k)` выражается линейной функцией от `PE(pos)`.

Пробовали и выученные позиционные эмбеддинги: результаты почти одинаковые (таблица 3, строка E). Синусоиды выбрали, потому что они, возможно, позволяют работать с последовательностями длиннее, чем встречались при обучении.

> **Комментарий.** Современные LLM используют третий вариант — RoPE (rotary position embedding): векторы запросов и ключей «поворачиваются» на угол, зависящий от позиции. Это развитие той же идеи про относительные позиции.

## 4. Почему именно self-attention

Авторы сравнивают слои трёх типов по трём критериям: вычислительная сложность на слой, сколько операций обязательно выполнять последовательно (то есть насколько всё параллелится) и какой длины путь проходит сигнал между двумя далёкими позициями. Короткий путь облегчает обучение дальних зависимостей.

Таблица 1 статьи (`n` — длина последовательности, `d` — размерность, `k` — ширина ядра свёртки, `r` — размер окна ограниченного внимания):

| Тип слоя | Сложность на слой | Последовательных операций | Макс. длина пути |
|---|---|---|---|
| Self-attention | O(n²·d) | O(1) | O(1) |
| Рекуррентный | O(n·d²) | O(n) | O(n) |
| Свёрточный | O(k·n·d²) | O(1) | O(logₖ(n)) |
| Self-attention с окном | O(r·n·d) | O(1) | O(n/r) |

*Источник: Vaswani et al., 2017, Table 1.*

Выводы авторов:
- Self-attention связывает любые две позиции за постоянное число шагов, а RNN — за `O(n)`.
- По вычислениям self-attention быстрее рекуррентного слоя, когда длина последовательности `n` меньше размерности `d`. Для предложений в переводе (с токенизацией на куски слов) это обычно так.
- Для очень длинных последовательностей можно ограничить внимание окном размера `r`. Путь тогда удлиняется до `O(n/r)`, это оставлено на будущее.
- Один свёрточный слой с узким ядром не связывает все пары позиций, нужна стопка слоёв, и пути удлиняются. Свёртки в целом дороже рекуррентных слоёв.
- Бонус: внимание интерпретируемо. По распределениям весов видно, что отдельные головы учатся разным задачам, многие явно связаны с синтаксисом и смыслом предложений (примеры в приложении статьи).

> **Комментарий.** Квадратичная сложность `O(n²·d)` — та самая причина, по которой длинный контекст дорогой. В 2017 году предложения были короткими, и это было неважно. Для LLM с контекстом в сотни тысяч токенов это одна из главных инженерных проблем.

## 5. Обучение

### 5.1. Данные и батчи

- **Английский → немецкий:** стандартный датасет WMT 2014, около 4,5 млн пар предложений. Токенизация BPE с общим для обоих языков словарём около 37 000 токенов.
- **Английский → французский:** WMT 2014, около 36 млн предложений, словарь word-piece на 32 000 токенов.
- В батч собирали пары предложений примерно одинаковой длины, около 25 000 токенов источника и 25 000 токенов перевода.

### 5.2. Железо и расписание

Одна машина с 8 GPU NVIDIA P100.
- **Базовая модель:** около 0,4 с на шаг, 100 000 шагов, итого 12 часов.
- **Большая модель:** около 1 с на шаг, 300 000 шагов, итого 3,5 дня.

### 5.3. Оптимизатор

Adam с `β₁ = 0.9`, `β₂ = 0.98`, `ε = 10⁻⁹`. Скорость обучения меняется по ходу обучения:

```
lrate = d_model^(−0.5) · min( step^(−0.5), step · warmup_steps^(−1.5) )      (формула 3)
```

То есть первые `warmup_steps = 4000` шагов скорость растёт линейно (прогрев), а потом убывает обратно пропорционально корню из номера шага.

### 5.4. Регуляризация

- **Residual dropout:** dropout на выходе каждого подслоя перед сложением с остаточной связью, а также на сумме эмбеддингов и позиционных кодировок. Для базовой модели `P_drop = 0.1`.
- **Label smoothing** со значением `0.1`: при обучении правильному токену дают не 100% вероятности, а немного меньше. Перплексия от этого ухудшается (модель учится быть менее уверенной), но точность и BLEU растут.

> **Комментарий.** Dropout — случайное «выключение» части чисел при обучении, чтобы модель не заучивала обучающие данные наизусть. Перплексия (perplexity) — мера того, насколько модель «удивлена» правильным ответом; чем ниже, тем лучше.

## 6. Результаты

### 6.1. Машинный перевод

- **EN → DE:** большая модель — 28,4 BLEU, больше чем на 2 пункта выше лучших опубликованных результатов, включая ансамбли из нескольких моделей. Даже базовая модель (27,3) обходит все прежние модели и ансамбли при доле их стоимости обучения.
- **EN → FR:** большая модель обходит все прежние одиночные модели при стоимости обучения меньше четверти от предыдущего лидера. В тексте раздела указано 41,0 BLEU, в аннотации и таблице 2 — 41,8.
- Для итоговых моделей усредняли веса последних контрольных точек (5 у базовой, 20 у большой) и использовали лучевой поиск (beam search) с шириной 4.

Таблица 2 статьи, сокращённо (стоимость обучения — оценка числа операций с плавающей точкой):

| Модель | BLEU EN-DE | BLEU EN-FR | Стоимость обучения, FLOPs |
|---|---|---|---|
| GNMT + RL | 24,6 | 39,92 | 2,3·10¹⁹ (EN-DE) |
| ConvS2S | 25,16 | 40,46 | 9,6·10¹⁸ (EN-DE) |
| ConvS2S, ансамбль | 26,36 | 41,29 | 7,7·10¹⁹ (EN-DE) |
| Transformer (base) | 27,3 | 38,1 | 3,3·10¹⁸ |

### 6.2. Вариации архитектуры

Авторы меняли по одному параметру базовой модели и смотрели на качество перевода EN → DE (таблица 3 статьи). Выводы:

- **Число голов (строки A):** одна голова хуже лучшего варианта на 0,9 BLEU, но и слишком много голов тоже ухудшает качество.
- **Размер ключа `d_k` (строки B):** уменьшение вредит. Похоже, определить совместимость не так просто, и функция сложнее скалярного произведения могла бы помочь.
- **Размер модели (строки C):** как и ожидалось, больше — лучше.
- **Dropout (строки D):** сильно помогает против переобучения.
- **Позиционное кодирование (строка E):** выученные эмбеддинги вместо синусоид дают почти тот же результат.

Для ориентира: базовая модель — 6 слоёв, `d_model = 512`, `d_ff = 2048`, 8 голов, **65 млн параметров**. Большая — 6 слоёв, `d_model = 1024`, `d_ff = 4096`, 16 голов, **213 млн параметров**.

> **Комментарий.** Строки C — ранний намёк на то, что потом назовут законами масштабирования. Для сравнения с сегодняшним днём: gpt-oss-20b, которую мы ставим в спринте 1, примерно в 100 раз больше большой модели из статьи.

### 6.3. Синтаксический разбор английского

Чтобы проверить, переносится ли архитектура на другие задачи, трансформер обучили на синтаксический разбор предложений (constituency parsing). Задача сложная: выход длиннее входа и подчиняется строгим структурным правилам, а RNN-модели на малых данных здесь не дотягивали до лучших результатов.

Модель с 4 слоями и `d_model = 1024`:
- только на 40 тыс. предложений WSJ (Wall Street Journal из Penn Treebank) — F1 = 91,3;
- в полуобученном режиме с ~17 млн дополнительных предложений — F1 = 92,7.

Почти без настройки под задачу она обошла все прежние модели, кроме Recurrent Neural Network Grammar, и, в отличие от RNN-моделей, превзошла BerkeleyParser даже на одном WSJ.

## 7. Заключение авторов

Transformer — первая модель преобразования последовательностей, целиком построенная на внимании: рекуррентные слои в энкодере и декодере заменены многоголовым self-attention. В переводе она обучается значительно быстрее рекуррентных и свёрточных архитектур и устанавливает новый лучший результат на обоих направлениях WMT 2014.

Планы авторов: применить внимание к задачам за пределами текста (изображения, аудио, видео), исследовать локальное ограниченное внимание для больших входов и сделать генерацию менее последовательной. Код был опубликован в библиотеке tensor2tensor.

## Словарик

| Термин | Что значит |
|---|---|
| Sequence transduction | Преобразование одной последовательности в другую (перевод, разбор) |
| RNN, LSTM, GRU | Рекуррентные сети: читают последовательность по одному элементу |
| CNN, свёртка | Сеть, которая смотрит на фиксированное окно соседних элементов |
| Энкодер / декодер | Часть, которая читает вход / часть, которая генерирует выход |
| Авторегрессия | Генерация по одному элементу, каждый раз с учётом уже сгенерированного |
| Self-attention | Внимание элементов последовательности друг на друга |
| Query / key / value | Запрос / ключ / значение — векторы в механизме внимания |
| Голова (head) | Одна из параллельных копий механизма внимания |
| d_model, d_k, d_v, d_ff | Длина вектора модели, ключа, значения, внутреннего слоя FFN |
| Residual connection | Остаточная связь: выход подслоя прибавляется ко входу |
| Layer normalization | Нормализация вектора, чтобы числа оставались в разумном масштабе |
| Softmax | Превращение произвольных чисел в вероятности, сумма которых равна 1 |
| BLEU | Метрика качества перевода, 0–100 |
| F1 | Метрика точности разбора, 0–100 |
| Beam search | Генерация, которая держит несколько лучших вариантов одновременно |
| Dropout, label smoothing | Приёмы против переобучения |
| FLOPs | Число операций с плавающей точкой, мера стоимости вычислений |
