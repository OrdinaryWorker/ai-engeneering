# ToyLLM: учебный прототип LLM

Маленькая, но настоящая LLM на чистом Python, только стандартная библиотека. В ней есть все части из [урока 01](../01-llm-basics.md): BPE-токенизатор, специальные токены, шаблон чата, эмбеддинги, слои трансформера с вниманием (RoPE, несколько голов, каузальная маска) и полносвязной сетью, выходная матрица, softmax и temperature. Инференс устроен как в [уроке 02](../02-how-llm-works.md): prefill, decode, KV-кэш, переиспользование кэша между ходами диалога, остановка по токену конца или по `max_tokens`.

Модель печатает в консоль каждый этап пути запроса с теми же номерами, что в уроке 02.

## Запуск

Из папки `toy-llm`:

```bash
python3 toy_llm.py chat "кто доставил заказ?"   # один запрос, подробный лог всех этапов
python3 toy_llm.py demo                         # 4 сценария, см. ниже
python3 toy_llm.py train                        # переобучить с нуля, ~4 минуты на CPU
```

Обученные веса уже лежат в `weights.json`, так что `chat` и `demo` работают сразу. Этот файл — «модель на диске» в миниатюре: внутри токенизатор (словарь и склейки), конфигурация и все числа весов.

Параметры `chat`: `--temperature` (по умолчанию 0.2), `--max-tokens` (30), `--num-ctx` (96), `--seed` (для повторяемости случайного выбора).

## Что модель знает

Её обучили на 12 коротких диалогах (список `DIALOGS` в начале `toy_llm.py`): «кто доставил заказ?» → «курьер доставил заказ.» и т.п. Данных так мало, что модель выучила их почти наизусть. На вопросы вне этого списка она будет отвечать бессмыслицей. Это нормально: так выглядит модель без предобучения на большом корпусе (урок 01, 5.2).

## Этапы урока 02 и код

| Этап урока 02 | Что печатается | Где в коде |
|---|---|---|
| 1. Запрос | JSON с сообщениями, temperature, max_tokens | `ToyLLM.chat`, начало |
| 2. Шаблон чата | Строка со специальными токенами и открытым `<\|assistant\|>` в конце | `Tokenizer.apply_chat_template` |
| 3. Токенизация | Каждый кусок и его номер, число токенов | `Tokenizer.encode_pieces`, `Tokenizer.encode` |
| 4. Контекстное окно | Вход + max_tokens против `num_ctx`, обрезка, если не влезает | `ToyLLM.chat`, проверка `num_ctx` |
| 5. Prefill | Сколько токенов взято из кэша, на кого «смотрит» последний токен, размер KV-кэша | `ToyLLM._reuse_cache`, `ToyLLM.forward` |
| 6. Decode | Таблица шагов: топ-3 кандидата с вероятностями и выбранный токен | цикл в `ToyLLM.chat`, `forward([next_id], cache)` |
| 7. Остановка | `stop` (выбран `<\|end\|>`) или `length` (кончился max_tokens) | цикл в `ToyLLM.chat` |
| 8. Ответ | JSON с текстом, причиной остановки, счётчиками токенов и таймингами, как у Ollama | конец `ToyLLM.chat` |
| 9. Следующий ход | Сценарий 2 в `demo`: история отправляется целиком, начало берётся из кэша | `ToyLLM._reuse_cache` |

Части модели из урока 01:

| Часть (урок 01) | Где в коде |
|---|---|
| 4.1 Токенизатор, BPE, специальные токены | класс `Tokenizer`, `Tokenizer.train` |
| 4.2 Таблица эмбеддингов | `self.w["embedding"]`, первая строка `forward` |
| 4.3 RoPE | функция `rope` |
| 4.4 Слой, остаточная связь, нормализация | цикл по слоям в `forward`, `add`, `rmsnorm` |
| 4.5 Внимание: запрос, ключ, значение, головы, маска | блок 1 в `forward`, матрицы `Wq`, `Wk`, `Wv`, `Wo` |
| 4.6 Полносвязная сеть | блок 2 в `forward`, матрицы `W1`, `W2` |
| 4.7 Выходная матрица, логиты, softmax | `self.w["output"]`, `softmax` |
| 4.8 Temperature, сэмплирование | цикл decode в `chat`: деление логитов на temperature, `rnd.choices` |
| 2. Обучение и инференс | `ToyLLM.train` (с градиентами через `Value`) и `ToyLLM.chat` (без градиентов) |

Ключевая идея кода: **одна функция `forward`** обслуживает и обучение, и prefill, и decode. Она прогоняет новые токены и дописывает их ключи и значения в KV-кэш. Prefill — это вызов с токенами всего входа, decode — вызов с одним токеном. Разница только в том, сколько токенов подаётся и что уже лежит в кэше.

## Сценарии `demo`

Ниже фрагменты реального вывода.

**1. Первый запрос.** Полный путь по этапам. Видно, как русские слова режутся на куски, сколько служебных токенов добавил шаблон и что модель выбирает слово за словом, пока не выдаст `<|end|>`:

```
шаг | топ-3 кандидата (вероятность после temperature)      | выбран
  1 | 'курьер' 100%, 'менеджер' 0%, 'пользователь' 0%      | 'курьер'
  2 | ' доставил' 100%, 'менеджер' 0%, ' оплатил' 0%       | ' доставил'
  3 | ' заказ' 100%, 'ч' 0%, 'ил' 0%                       | ' заказ'
  4 | '.' 100%, 'ст' 0%, ' сделал' 0%                      | '.'
  5 | '<|end|>' 100%, '<|assistant|>' 0%, ' оплат' 0%      | '<|end|>'
```

**2. Второй ход диалога.** История уходит целиком, вход вырос с 7 до 20 токенов. Но первые 11 токенов совпадают с прошлым запросом, и движок берёт их из KV-кэша:

```
Начало входа совпало с прошлым запросом: из KV-кэша взято готовыми 11 ток., считаем только 9 новых
```

**3. Temperature.** Один вопрос, по 5 ответов. Модель очень уверена в выученном ответе, поэтому при 0.1 и 1.0 ответы одинаковые. При 3.0 распределение размазывается, маловероятные куски начинают выпадать, и получается мешанина:

```
temperature=3.0:
   'курьер доставил заказ.'
   'мпривекурьер?'
   'закаемк.тпри достку.закаиле'
```

**4. Маленький max_tokens.** Ответ обрезан на 3 токенах, причём посреди слова: «перед» вместо «передать заказ менеджеру.», `done_reason: length`.

## Чем ToyLLM отличается от настоящих моделей

| | ToyLLM | gpt-oss-20b |
|---|---|---|
| Параметров | ~9 тысяч | ~21 миллиард |
| Словарь | 90 токенов, BPE из символов | ~200 тысяч, BPE из байтов |
| Размерность вектора | 16 | тысячи |
| Слоёв / голов | 2 / 2 | десятки / десятки |
| Полносвязная сеть | одна в слое | смесь экспертов (MoE) |
| Обучение | 12 диалогов, 4 минуты на CPU | триллионы токенов, тысячи GPU |
| Prefill | цикл по токенам | одна матричная операция на GPU |

Математика при этом та же. Если увеличить размеры и данные, ничего в устройстве менять не нужно.

## Задания

1. Запусти `chat` с вопросом не из обучающего списка, например `chat "где мой телефон?"`. Посмотри на вероятности в таблице decode. Потом повтори с `--temperature 1.0`. Что изменилось и как это связано с галлюцинациями из урока 01?
2. Запусти `chat "заказ не оплачен. что делать?" --num-ctx 20`. Что произошло на этапе 4 и как это отразилось на ответе?
3. Найди в выводе этапа 3 слово, которое разбилось на несколько токенов. Почему именно оно? Подсказка: посмотри склейки, которые печатает `train`.
4. В функции `forward` закомментируй строку `xs[i] = add(xs[i], linear(head_outputs, W("Wo")))` (это отключит внимание) и переобучи модель с `train --steps 600`. Сможет ли она отличать вопрос про курьера от вопроса про менеджера? Почему? Верни строку и переобучи обратно, либо восстанови `weights.json` через `git checkout`.

<details>
<summary>Подсказки к ответам</summary>

1. При temperature 0.2 модель отвечает бессмыслицей вроде «привеменеджер отправилку.», и почти у каждого шага 100%. Низкая temperature заострила распределение, и уверенность выглядит полной, хотя ответ выдуман. При 1.0 видно реальную картину: у первого токена 56% / 17% / 14%, модель не знает, что сказать, но всё равно выбирает. Сказать «не знаю» она не умеет. Это галлюцинация в миниатюре и заодно иллюстрация того, что низкая temperature от галлюцинаций не спасает (урок 01, вопрос 4).
2. Вход плюс max_tokens не влез в окно, и движок отрезал начало входа. Модель не увидела начало вопроса (а возможно, и `<|user|>`), поэтому ответ стал случайным. Ошибки при этом нет: обрезка происходит молча.
3. Обычно режутся слова, которые редко встречались в обучающих текстах. Частые сочетания букв («заказ», «ил», «ер») склеились первыми, а редким словам склеек не хватило, и они собираются из нескольких кусков. Это ровно причина, по которой русский текст в настоящих моделях дороже английского.
4. Без внимания токены не обмениваются информацией: каждый вектор знает только свой токен. Последний токен входа `<|assistant|>` одинаковый во всех вопросах, поэтому модель не может узнать, о ком спрашивали, и отвечает одним и тем же или смешивает ответы.

</details>

## Модель-подсчёт для сравнения

`step1_ngram.py` и `corpus.txt` — совсем простая «языковая модель» на `dict`: считает, какое слово шло после двух предыдущих. Внимания и весов там нет, только таблица частот. Полезно запустить её рядом с ToyLLM и увидеть разницу: n-граммная модель видит только два последних слова, а трансформер — весь контекст. Цифры про temperature из урока 01 (раздел 4.8) получены именно ею.

```bash
python3 step1_ngram.py
```
