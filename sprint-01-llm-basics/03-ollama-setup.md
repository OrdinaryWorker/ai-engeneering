# Поднимаем локальную модель

Схема: Ollama работает на рабочей станции (Ubuntu, 2× RTX 5090) и слушает только `localhost:11434`. С ноутбука ходишь к нему через SSH-туннель. Код курса пишешь и запускаешь на ноутбуке.

Почему туннель, а не открыть порт в сеть: у Ollama **нет авторизации**. Любой, кто достучится до порта, сможет гонять модели и скачивать новые.

## Шаг 1. Драйвер NVIDIA (на станции)

5090 — это архитектура Blackwell. Ей нужен драйвер версии 570 или новее, в варианте с открытыми модулями ядра (пакет с суффиксом `-open`).

```bash
sudo apt update
ubuntu-drivers devices          # посмотри, какой драйвер рекомендуется
sudo ubuntu-drivers install     # или: sudo apt install nvidia-driver-<версия>-open
sudo reboot
nvidia-smi                      # должны быть видны обе карты по ~32 ГБ
```

CUDA Toolkit отдельно ставить не нужно, Ollama несёт свои библиотеки.
Если включён Secure Boot, при установке драйвера Ubuntu попросит задать пароль для подписи модуля. После перезагрузки его нужно ввести в синем экране MOK.

## Шаг 2. Ollama (на станции)

Официальный установщик (перед запуском открой скрипт и посмотри, что он делает):

```bash
curl -fsSL https://ollama.com/install.sh -o install.sh
less install.sh
sh install.sh
systemctl status ollama           # сервис должен быть active
journalctl -u ollama -n 50        # в логе должны найтись обе GPU
```

### Контекстное окно по умолчанию

Ollama по умолчанию даёт модели маленький контекст (несколько тысяч токенов), даже если модель умеет 128K+. Длинный вход молча обрежется. Это прямое продолжение темы про контекстное окно из [01-llm-basics.md](01-llm-basics.md). Поставь побольше через override сервиса:

```bash
sudo systemctl edit ollama
# в открывшемся файле:
# [Service]
# Environment="OLLAMA_CONTEXT_LENGTH=32768"
sudo systemctl restart ollama
```

Вопрос себе: почему не поставить сразу максимум? (Подсказка: память под KV-кэш растёт с длиной контекста.)

## Шаг 3. Модель (на станции)

Стартовые кандидаты, обе хорошо держат tool calling и понимают русский:

- `gpt-oss:20b` — MoE, около 14 ГБ, быстрая;
- одна из свежих Qwen на ~27–32B (например, `qwen3.5:27b`), около 17–20 ГБ.

Актуальные теги проверь на https://ollama.com/library: линейки обновляются часто, и я могу ошибаться в последних версиях.

```bash
ollama pull gpt-oss:20b
ollama run gpt-oss:20b "Привет! Ответь одним предложением, кто ты."
ollama ps                          # сколько памяти заняла модель и на каких GPU
```

## Шаг 4. SSH-туннель (на ноутбуке)

```bash
ssh -N -L 11434:localhost:11434 user@<адрес-станции>
```

Пока команда висит, `localhost:11434` на ноутбуке ведёт в Ollama на станции. Проверка из второго терминала:

```bash
curl http://localhost:11434/api/tags
```

## Шаг 5. Первый вызов «руками» (на ноутбуке)

Через OpenAI-совместимый эндпоинт, тот же формат будет у vLLM:

```bash
curl http://localhost:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-oss:20b",
    "messages": [{"role": "user", "content": "Объясни, что такое токен, в двух предложениях."}]
  }'
```

Разбери ответ сам и запиши:
- где текст ответа и с какой ролью он пришёл;
- что лежит в `usage` (сколько токенов на входе и выходе);
- что в `finish_reason` и какие ещё значения там бывают (попробуй добавить `"max_tokens": 10`).

## Шаг 6. Практика: считаем токены

Отправь три текста из практики в [01-llm-basics.md](01-llm-basics.md) (русский, тот же на английском, кусок кода) и сравни `usage.prompt_tokens`. Учти, что в число входят и служебные токены шаблона чата. Как их вычесть, подумай сам: подсказка: отправь сообщение из одного слова и посмотри, сколько токенов насчиталось.
